# Simple three-phase setup — design

Date: 2026-10-19 · Status: implemented

## Problem

Getting the stack running on a fresh clone takes eight manual steps (`make init-env`, edit `.env`, a bash loop to copy credential templates, edit credentials, `make check-env`, `make up`, a separate `docker compose --profile proxy up -d proxy`, `make seed-demo DEMO_PASSWORD=…`). Teammates miss steps, most often the proxy (no web UI) and the demo seed (no login). The file layout (`.env`, `domains/*/credentials/*.env`) is fine and stays.

## Goal

Three phases, each with one obvious action, and a teammate-facing guide in English and Vietnamese:

```text
1. make setup        create .env + credential files, list what to fill
2. edit files        then `make check` until it passes
3. make up           check, start everything incl. the web UI, seed demo users, print URLs
```

Non-goals: Windows-native support (no `make`/bash), interactive prompting for secrets, changes to `docker-compose.yml` or the EC2 deploy, a shared-secrets bundle.

## Phase 1 — `make setup`

Makefile target, safe to re-run:

1. Tool check: `docker compose version` and `docker buildx version`; on failure print which one is missing and point to `GUIDE.md` (buildx is required by the `RUN --mount=type=cache` lines in all three Dockerfiles).
2. Run `python -m backend.init_env` in `python:3.12-slim` (as today's `init-env`), extended as below.

`backend/init_env.py` (stays stdlib-only, so it needs no image build) gains:

- **Credential templates.** For every `domains/*/credentials/*.env.example` without a sibling `*.env`, create it from the template with mode 600 (reusing `_write_private`). Existing files are never touched. Prints `created domains/<id>/credentials/<set>.env` per new file.
- **To-fill report.** After writing, list every empty key the operator must set, grouped by file, names only, never values:
  - `.env`: the operator keys `OPENROUTER_API_KEY`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` (required) and `DEMO_PASSWORD` (optional, labelled so).
  - each `domains/*/credentials/*.env`: every empty key.
  - Ends with `next: fill these, then run make check` (or `nothing to fill; run make up` when all set).
- The marker comment `# Generated by make init-env` becomes `# Generated by make setup`.

`.env.example` gains, in the operator section:

```text
# optional: password for the demo users alice (fabrikam) and bob (re-marketing); make up creates them
DEMO_PASSWORD=
```

and its header and "Generated by" comments name `make setup`. `Settings` already uses `extra="ignore"`, so the new key needs no settings change.

## Phase 2 — edit files, `make check`

The teammate edits `.env` and the credential files following the guide's table, then runs:

- `make check` → `docker compose run --rm --no-deps --build backend python -m backend.preflight` (today's `check-env`, renamed). Semantics unchanged: non-zero exit only on missing platform keys; a domain with missing credentials is reported `unavailable` with its reason but does not fail. The first run builds the backend image, which `make up` reuses.

## Phase 3 — `make up`

1. `make check`; stop on failure.
2. `docker compose --profile proxy up -d --build --wait` — the proxy (web UI on `127.0.0.1:${PROXY_PORT:-8080}`) is always started locally. `docker-compose.yml` is unchanged, so the EC2 `docker compose up -d` keeps its current service set.
3. If `.env` has a non-empty `DEMO_PASSWORD`: `docker compose exec -T backend python -m backend.seed_demo` (the backend container already has `.env` via `env_file`; seeding skips existing users, so every `up` is safe). Otherwise print `DEMO_PASSWORD not set; skipping demo users`.
4. Print:

```text
VDaAgent is up
  app       http://localhost:<PROXY_PORT or 8080>   (login: ADMIN_USERNAME [, alice, bob])
  api       http://127.0.0.1:<APP_PORT or 8000>/api/health
  langfuse  http://localhost:3100                    (admin@contoso.local / ADMIN_PASSWORD)
```

Ports come from `.env` when set, else the compose defaults.

`make down` and `make logs` are unchanged (`down` already stops the proxy via `--profile '*'`).

## Makefile surface

| Target | Change |
|---|---|
| `setup` | new (replaces `init-env`) |
| `check` | renamed from `check-env` |
| `up` | runs `check`, adds `--profile proxy`, seeds, prints URLs |
| `init-env`, `check-env`, `seed-demo` | removed, no aliases |
| `down`, `logs`, `test*`, `lint`, `format`, `lock`, `e2e`, `eval` | unchanged |

`make help` lists `setup`, `check`, `up` first. The empty `dev.ps1` at the root is deleted.

## Guide

`GUIDE.md` (English, canonical) and `GUIDE.vi.md` (Vietnamese mirror) at the repo root, each linking to the other at the top. Sections:

1. **Prerequisites** — Docker with compose and buildx (install hints for macOS, Linux, Windows via Docker Desktop + WSL), `make`, `git`; disk/RAM needs measured from a real `make up` (`docker system df`, `docker stats`), not guessed. No Python/Node/uv on the host.
2. **Phase 1** — `make setup`, sample output.
3. **Phase 2** — table: file → key → meaning → where to get it. Sources: `OPENROUTER_API_KEY` from the project owner (shared platform key, decision 0008); `ADMIN_*`/`DEMO_PASSWORD` chosen by you; `WAREHOUSE_DSN`, `WAREHOUSE_SNAPSHOT_ID` and `TAVILY_API_KEY` from the project owner, sent privately. Recommended model lines (`AGENT_MODEL`, `JEV_MODEL`, `COMPACTION_MODEL`) to avoid the costly Haiku default. Then `make check` with sample output and how to read `unavailable`.
4. **Phase 3** — `make up`, what it prints, `make down`, `make logs`.
5. **Troubleshooting** — port taken (`APP_PORT` + `APP_URL`, `PROXY_PORT`); buildx missing; domain `unavailable`; task stuck in `running` (OpenRouter credits, `model_unavailable` error events); remote Docker host (run in a checkout on the host, tunnel 8000/8080/3100; never `DOCKER_HOST=ssh://` from the laptop, because bind mounts resolve client-side); 403 `csrf` on hand-made API calls (`X-Contoso-Client: web`).
6. **Rules** — never commit `.env` or `domains/*/credentials/*.env`.

## Testing

- `backend/tests/unit/test_init_env.py` gains cases for the new behaviour: a missing credential file is created from its template with mode 600; an existing one is left byte-identical; the report lists empty operator and credential keys by name and never prints a value; a fully filled tree reports nothing to fill.
- Smoke on a throwaway clone with no `.env` and no credential files: `make setup` (files created, report lists keys) → `make setup` again (nothing overwritten) → `make check` fails naming the keys → fill → `make check` passes → `make up` → health returns `{"ok":true,"db":true,"execd":true}`, `:8080` serves the SPA, alice logs in → `make down`.
- `make test` and `make lint` stay green.

## Risks

- `make up` now always builds the backend twice in the worst case (check, then up); the second is a cache hit, so cost is seconds.
- Removing `init-env`/`check-env`/`seed-demo` breaks muscle memory; the guide and `make help` are the only pointers. Accepted per clean-cutover.
