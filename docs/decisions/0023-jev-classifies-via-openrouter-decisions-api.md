# 0023 · jev classifies via OpenRouter's Decisions API, not a chat LLM

- **Context.** jev (doc 07 "jev") is named after TypeSafe AI's "Jev" model — a non-generative "System One" decision model that returns typed, probability-scored answers instead of free text — but it was implemented as a regular chat-completion call (`JEV_MODEL`, a free-text system prompt in `platform/jev.md` asking for `{"label", "description"}` JSON). OpenRouter's Decisions API (`POST /api/alpha/decisions`) reaches the real Jev model, on the same `OPENROUTER_API_KEY` already in `.env`.
- **Decision.** `ModelClient.decide()` posts a single `choice` question (`route`, criteria from `platform/jev_criteria.yaml`) to the Decisions API and gets back `{choice, probabilities, confidence}`. `description` is dropped end-to-end (DB column, API field, frontend type): Jev cannot write prose, and the field was already dead in the admin UI. Task titles fall back unconditionally to the source message's text, truncated to 500 chars. A new setting `JEV_CONFIDENCE_FLOOR` (default `0.6`) forces the stored `label` to `side_question` when jev's `confidence` is below it, replacing the old prompt's "when unsure, choose side_question" instruction as the mitigation for the documented deadlock risk (doc 99: "jev mislabels help as a task"). **Model id:** verified live against the running stack — `typesafe/jev-1.13` and `typesafe/jev-1.14` both resolve; `typesafe/jev-latest` returns 400 `does not exist`. `JEV_MODEL` defaults to `typesafe/jev-1.14` (the current one); `-1.13` stays the documented-working fallback.
- **Rejected.** A confidence-gated escalation to a chat LLM on low confidence: that's a second, more complex design the user explicitly didn't ask for. Pure replacement only.
- **Unchanged.** [0002](0002-jev-reads-the-receivers-view.md) (jev reads the receiver's rendered view, not raw events) and [0008](0008-platform-openrouter-key-no-byok.md) (one OpenRouter key, no BYOK) both still hold: the context-building policy and the credential model are untouched, only the call mechanism changed.
- **Consequences.** `jev_decisions.description` history (real Vietnamese text) is lost on migration — acceptable, it's a decision log, not an audit trail; `observed` mislabel marks (the accuracy-measurement mechanism) are untouched. `JEV_CONFIDENCE_FLOOR=0.6` is an unvalidated guess (the underlying paper's recommendation), acceptable for a PoC and tunable without a code change. See [07](../07-routing-and-queue.md#classification), [03](../03-agent-loop.md#model-calls).
